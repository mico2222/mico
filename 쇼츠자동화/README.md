# 쇼츠자동화

대본을 넣으면 목소리·자막·그림이 자동으로 배치된 세로(1080x1920) 캡컷 초안을
만들어주는 프로그램입니다. 최종 내보내기는 캡컷에서 직접 합니다.

## 처음 시작할 때 (윈도우 컴퓨터에서)

1. 이 폴더를 통째로 바탕화면에 옮겨두세요 (`쇼츠자동화` 폴더).
2. `env.txt.example` 파일을 복사해서 이름을 `env.txt` 로 바꾸고, 안의 경로를
   본인의 구글 서비스 계정 키(json) 파일 경로로 고쳐주세요. 아직 키가 없다면
   비워둔 채로 넘어가도 됩니다 — 목소리는 무음으로 대신 채워집니다.
3. `검증실행.bat` 을 더블클릭해서 0단계 검증을 돌려보세요. 결과는 화면과
   `검증결과.txt` 파일에 남습니다. A 항목이 전부 통과해야 다음으로 넘어가는
   의미가 있습니다.
4. `실행.bat` 을 더블클릭하면 필요한 프로그램을 자동으로 설치하고 브라우저가
   열립니다. 첫 화면에서 [도구 설치] 버튼으로 나머지 파이썬 꾸러미도 설치하세요.
5. "새 작업" 탭에서 대본을 붙여넣고 "만들기"를 누르면 목소리·자막 정렬·씬
   분할까지 자동으로 진행됩니다 (여기까지는 돈이 들지 않습니다).
6. "검수 화면"에서 씬마다 이미지를 만들거나(장당 약 55원) 내 파일을 올리고,
   위치를 맞춘 다음 "검수 승인" → "캡컷 초안 만들기" 순으로 누르세요.
   승인하기 전에는 어떤 영상 변환도 돌지 않습니다.
7. 캡컷을 열면 방금 만든 초안이 목록에 보입니다.

## 이 코드가 만들어진 방식에 대한 중요한 안내

이 프로젝트는 **클라우드 원격 세션**(Claude Code on the web)에서 작성되었습니다.
즉, 이 코드를 작성한 환경은 사용자의 실제 윈도우 컴퓨터가 아니라 매번 새로
생성되는 리눅스 컨테이너였고, 캡컷·구글 클라우드 로그인 화면·사용자의 실제
파일 시스템에는 접근할 수 없었습니다. 그래서:

- **원래 요청에 있던 "명령어를 나 대신 실행해라, 화면 캡처를 보고 알려줘라"는
  이 세션에서는 할 수 없었습니다.** 그 대신 코드 자체를 최대한 완성도 있게
  작성하고, 이 저장소 안에서 실제로 실행 가능한 부분은 전부 실행해서
  검증했습니다.
- **실제로 검증한 것** (이 리눅스 환경에 ffmpeg/claude CLI/pycapcut을 설치해서 확인):
  - 대본 검사 로직 (글자 수·문장 수·훅 길이·금지 문자)
  - 자막 줄바꿈 실측 공식과 수관형사 뒤 줄바꿈 방지 로직 — 문서의 예시
    ("오늘 저녁에" / "딱 한 번만" / "돌려보세요")와 정확히 일치함을 확인
  - 세로 화면 점유율 공식 (16:9→32%, 4:3→42%, 1:1→56%, 0.85:1→66%,
    0.75:1→75%, 9:16→100%) — 문서의 실측값과 소수점까지 일치함을 확인
  - `claude -p` 실제 호출 → JSON 봉투/삼중따옴표 파싱 → 씬 분할 → 문장 커버리지
    검증 → timing.json 기준 시간 재계산까지 **실제 클로드 코드 CLI로 실행해
    정상 동작을 확인**
  - pycapcut 으로 실제 캡컷 초안(draft_content.json) 생성 — 오디오 트랙,
    배경 트랙, 자막 트랙(53개 자막 조각, 겹침/틈 없음)까지 실제 생성 확인
  - 씬 이미지 업로드 → 배치 모드 변경 → 미세/보통 이동(방향 반전 포함) →
    정중앙 리셋까지 API 전체 흐름 확인
- **검증하지 못한 것** (이 환경에는 윈도우·캡컷·구글 클라우드 결제 계정이
  없어서): 캡컷 앱에서 실제로 초안이 열리는지, 파이썬 자동 설치가 실제
  윈도우 npm/claude.cmd 환경에서 매끄럽게 되는지, 구글 TTS/이미지 생성 API
  실제 호출, faster-whisper 의 실제 정렬 품질. 이 부분들은 **검증실행.bat 을
  본인 컴퓨터에서 직접 돌려서 확인해야** 합니다. 검증에서 안 되는 항목이
  나오면 화면에 뜨는 한국어 설명을 따라가면 됩니다.
- 롱폼 재활용 모드(`pipeline/recycle.py`, `pipeline/broll.py`)는 참고할 실제
  롱폼 자동편집기 폴더가 이 환경에 없어 문서에 적힌 실측값(파일명 규칙,
  세로 적합도 점수, 크로마키 비율 임계값 등)을 그대로 코드로 옮겼습니다.
  `config.yaml` 의 `modes.recycle: false` 가 기본값이며, 실제 롱폼 폴더가
  있는 컴퓨터에서 켜서 파일명 규칙이 맞는지 확인해주세요.

## 폴더 구성

- `config.yaml` — 기술 설정 + 브랜드. 사람이 직접 고치는 유일한 파일 (주석 있음)
- `env.txt` — 구글 키 경로 (비밀, git에 올리지 않음)
- `실행.bat` / `검증실행.bat` — 더블클릭용
- `run.py` / `verify.py` — 위 배치 파일이 실제로 실행하는 파이썬 진입점
- `assets/character_sheet_916.png` — 상황극 인물 참조 (직접 준비, `assets/README.md` 참고)
- `prompts/scene_plan_shorts.md` — 씬 분할 프롬프트
- `pipeline/` — 실제 처리 로직 (공통 유틸/클로드 호출/TTS/정렬/씬 분할/이미지 생성/
  세로 배치/자막/조립/실행기/롱폼 재활용/B롤 회수)
- `server/` — 로컬 웹 화면 (FastAPI + 순수 JS)
